# Real coding pairs: protocol 2

This prospective extension leaves protocol 1's frozen runner, startup-censored native probe and
manifests intact. It adds held-out assignment preparation and collection in `real_repo_pairs.py`.
It does not resolve the previous unknown bill, spend money during preparation, or manufacture
training evidence. The existing shared `paid-state.json` remains the admission authority; its
unresolved attempt blocks every later live dispatch.

## Inputs and preparation

The original five-training/two-held-out split per repository remains unchanged. Once production
learning succeeds from the ten actual native training transcripts, save a descriptor for each
family with these fields:

```json
{
  "family": "click-type",
  "action_kind": "verify",
  "learned_home": "/absolute/path/to/actual/learned/home",
  "files": ["index.json", "tracks/example/learned/track.toml"],
  "route": "actual-track/learned/actual-route-id",
  "training_tasks": ["the exact five prospectively assigned task IDs"],
  "condition_command": ["the actual production condition invocation"],
  "condition_output": "/absolute/path/to/actual-condition-output.json",
  "binaries": {"adage": "/absolute/path/adage", "adage-exec": "/absolute/path/adage-exec"},
  "model": "claude-haiku-4-5-20251001"
}
```

The paths and route above are schema examples, not seeded reflexes. Supply every static file that
the real learned artifact needs. Preparation requires the exact route in the production learned
index, five original native transcript hashes, and the actual condition output. Production
eligibility and evidence certificates still decide whether the learned candidate is valid.

Run `real_repo_pairs.py prepare ROOT TASK DESCRIPTOR` for each held-out task. Both arms receive
byte-identical learned artifacts, the same task prompt, model, available tools, offline permissions
and clean pinned source. The predefined seeded order is retained in `pair.json`. The observer calls
`adage hook` for suggest and `adage-exec hook` for automatic; it returns their output unchanged.
No family-specific matcher or instruction to omit agent tests is added. Future preparation records
new helper/binary/artifact hashes without altering prior protocol manifests.
An assignment manifest digest detects later argument edits. Dispatch also compares the untouched
checkout to its prepared source snapshot. Pair comparison requires identical initial source, base
commit, model, binary hashes, protocol sources, normalized permission settings and training IDs.

Each assignment has an independent Adage home to prevent cooldown or previous-session state from
crossing arms. Grants, session state and execution journals are excluded from artifact copying.
A person must approve each automatic home's concrete route with the normal product CLI; this
helper never creates, copies, edits or revokes approval records. Missing grants block dispatch.
Before any live pair, the actual installed Claude sandbox probe must pass human evidence review.

## Observation and scoring

The wrapper records hook input/output, process status, timing, whole-source file hashes before and
after each invocation, and new receipts returned by the production journal CLI. That CLI performs
the authoritative strict journal validation. The source generation includes untracked files and
excludes only Git metadata, the prepared virtual environment and named Python tool caches.
No symlink is followed while hashing. Hook observer overhead is separately timestamped and remains
included in overall live session latency.

Collection keeps the native transcript, tool calls/results, production session spool, all execution
attempts including misses/refusals, authoritative receipts, final source hashes, tracked patch,
actual cost and observed API request dispatch IDs. It keeps an entire independent scoring checkout,
including new files. Dependencies are installed from the trusted pinned base before agent-written
source is copied into the scoring checkout; modified build backends never run during installation.
The resulting source must exactly match the captured final generation. Hidden tests then run using
the existing scorer under the previously validated offline Seatbelt boundary. Source symlinks fail
closed pending a separate review rather than being followed by the scorer.

Before model dispatch, `freeze-hidden ROOT TASK` runs the unchanged trusted gold hidden tests under
the same confinement and freezes their complete parametrized identities from JUnit. Independent
scoring instruments the existing pytest command with JUnit reporting, without modifying the shared
showcase scorer. Every expected hidden case must be present exactly once with a successful call;
skips, xfails, collection filters, missing cases, duplicate identities, setup errors and failures
reject quality even if pytest exits zero and other tests pass. Dependency installation is offline
and pins the exact dependency versions captured during original preparation.

## Acceptance

A pair requires two successful, uncensored processes with reported costs within $1.50 each and
independent hidden/whole-suite quality passes. The baseline must successfully perform the actual
learned command; the automatic arm must omit it and reduce total agent tool actions. Matching uses
the learned argv template, not repository/family heuristics. Additionally, the automatic arm must
make no agent pytest invocation through either admitted entry point, regardless of flags or selectors.
This conservative evaluator counter prevents a renamed/reflagged verification from masquerading as
an eliminated action. It does not influence production prediction. Preserve all commands for review.

Automatic execution must have a completed, successful E2 verify receipt for the correct session,
route and worktree, with approval identity and production input digest. The observer's source
generation immediately before and after that action must equal the final submitted source.
A later source edit, failed/unknown receipt, source mutation, replay without a new observed receipt,
foreign worktree or incomplete journal cannot establish final verification. Repeated CPU executions
remain visible and must be reported as overhead.

Action savings and inference savings are separate results: `observed_inference_reduction` additionally
requires fewer observed API dispatches in the automatic arm. There is no inference-energy claim and
no general productivity claim from four pairs. Report every assignment, including setup errors,
quality failures and censored sessions; no outcome retry or selective exclusion is permitted.
