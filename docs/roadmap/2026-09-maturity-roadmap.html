Adage · maturity roadmap

Agent traces become reflexes

2026-09-27 · branch claude/repo-maturity-roadmap-l95ohs · base ce5e311 · compiled from four research passes over the code, the eval data and the current external benchmark landscape

Adage's delivery half (fixed templates, slot contracts, effect ceilings, content-addressed index, pure decide(), fail-open hooks) is already built to a high-assurance standard. The learning half is five imitation-rate miners with no decay and no causal estimate, and the eval stack cannot yet support tuning decisions. The plan: fix measurement first, then make evidence trustworthy, then widen what the engine learns, including instincts and skill-trained reflexes. Every change is scored against one benchmark ladder.

Findings that reset priorities

checked against code and data

Four of these findings change the order of work. I re-checked the first three directly against the repository, not only through the agents' reports.

Round-2 headline is not held out

The round2 split in evals/datasets/demo-haiku45 trains on 36 round-1 eval sessions of W-2041…W-2046, then tests on round-2 sessions of the same six tasks. The live runner does the same (evals/live/runner.py:556). Routes are repository conventions, so this is milder than it sounds. Still, the "20 → 2 turns" figure and most of the gate floors rest on it, and it breaks Design Spec's own "held-out tasks for every published number."

Fix: task-grouped and temporal splits in dataset.rs, a fresh held-out task pool per round, and a caveat on the README numbers until they are re-run.

A harm signal went unreported

Haiku round 1: the Adage arm hit 26 failed verify runs and the control arm hit 0. Skipping exploration also skipped the agent's incidental discovery of make test. Round 2 learned a dead-end route that fixed it, but no metric treats "a directive caused a side-effect regression" as a guardrail.

Fix: harm metrics (failed_after_follow, verify_fail_after_directive) become hard guardrails in the scorecard.

Useful routes can starve themselves of evidence

Each miner drops sessions steered by its own kind (adage-learn/src/lib.rs:238). Once a route is delivered, only the ~10% holdout sessions keep counting. When pre-install transcripts expire (Claude Code keeps 30 days), routes that weak agents never find unaided fall below min_support. reconcile then drops them. The most valuable routes retire themselves, get relearned, and the cycle repeats. No test covers this, because evals learn once.

Fix: a Stale state that holds a route instead of dropping it when support loss comes from exposure rather than contrary evidence, plus a retention-ageing replay gate.

The control arm isn't isolated or randomized

Arm order is fixed (holdout before adage, runner.py:130). Both arms share the operator's Claude Code auto-memory: holdout agents read MEMORY.md in 23/36 runs, adage agents in none. Sandboxes also sit next to adage-home/. Effective n is about 6 tasks, not 18 runs. p-values shuffle runs, not tasks, and infra failures count as task failures.

Fix: per-run HOME/CLAUDE_CONFIG_DIR, a seeded arm order, task-cluster statistics, and status ∈ {ok, infra_error, censored, scorer_error}.

1 · Graph and predictive engine

first principles

What the engine is today

Mathematically, it is a set of independent, first-order association rules:

  • Each rule maps (a predicate over one event plus features of the first prompt) to one step.
  • Each rule carries a Bernoulli estimate, "P(agent does X | trigger)", counted over distinct sessions.
  • A threshold policy (Wilson LB ≥ 0.8 → green; rate ≥ 0.5 → yellow; effect ceiling) turns that estimate into an aspect.

The only chaining is lookup → linked files. SessionState.history (32 keys) is written but never read. The variable-order (PPM/TAGE) model in Design §8.5 was not built.

The estimate is imitation propensity: how often agents already do X. It is not the effect of telling them to. For discovery routes, the value of a directive is roughly (1 − punaided) × benefit, so the evidence gate and the value point in opposite directions.

Excellent; keep as is

  • Fixed-template rendering, typed slot contracts, effect ceilings with effects re-derived from commands, and an independent safety oracle. Structure comes from data; prose comes from code.
  • Content-addressed index, atomic swap, and a pure decide(): 36/36 live decisions reproduce byte for byte.
  • A fast path proven equivalent on every eval event.
  • Two-slot CRC state, CRC-framed spools, and rebuilds that fail toward silence.
  • Purity split/merge ("embeddings propose, behaviour decides") and signature-keyed dead ends.

Where it is brittle

  • Three matching semantics for "the same command": exact key, command head, and token prefix. make gen -j4 never meets a make gen obligation. npm run build counts as following npm run check, which inflates both live follow rates and offline precision.
  • One lookup route per repository, and finish-line globs only one level deep.
  • Failure attribution is per call. In make gen && pytest, a pytest failure marks make gen as failed.
  • Winner's curse. The intent threshold is picked in-sample to maximise Wilson LB, and that same LB is reported as evidence.
  • No interlocking. An imported "start with npm test" and a learned "npm test fails" can both fire at prompt 1.
  • The "CI fails if this is skipped" text is unmeasured, because deviations_failed is almost always 0.

What transfers from high-assurance deterministic systems

The guiding principle comes from railway signalling: separate the proposer from the interlocking. Learners may be clever and probabilistic. What reaches the agent passes a small, deterministic, verifiable gate. Adage already has the output stage. It lacks the evidence layer (causal, calibrated, decaying) and the interlocking layer (conflicts between routes).

2 · Training mechanisms and instincts

team corpus · consumer modes · shipped instincts

Instinct = a prebuilt route that ships in the binary as a template plus a detector. At learn time it binds per repository from repository files, never from history, so it works on day 0. It is capped at yellow and loses to any reflex that contradicts it. Reflex = a learned route compiled from sessions: organic history, or sessions Adage drove from a skill. Every route Adage has today is a reflex.

Evidence origin: one field, which makes the rest possible

Each count records where it came from. The existing support/opportunities fields stay organic only, so gates and review bases keep their meaning. A new Evidence.by_origin holds the other counts. They are kept separate rather than merged into a weighted count, because a weighted Wilson bound is meaningless.

A · Internal training data for the team

Sandbox generator driven by a convention grammar

Replace the two hand-built sandboxes with evals/gen/, which composes three parts:

  • Stack template: python-make, uv, npm, pnpm monorepo, cargo workspace, go, polyglot.
  • Domain skin: the surface vocabulary and modules.
  • Typed convention instances (lookup, dead_end, finish_line, scope, env_sync), serialised to conventions.json as ground truth.

Two instance kinds matter most:

  • Decoys, which look like conventions but aren't. They measure the false-route rate.
  • Instinct violations, where the universal default is wrong. They measure whether reflexes override instincts.

A generalised selfcheck proves each convention holds before any tokens are spent.

Run matrix and the simulator

  • Harnesses: Claude Code, Codex and OpenCode headless. This also closes R9: OpenCode and Codex have not been verified live.
  • Models: a cheap volume tier, a strong ceiling tier, and one non-Anthropic model per harness.
  • New arms: instincts-only, skill-in-context, poisoned-track.
  • adage-sim becomes grammar-driven, with behaviour profiles fitted to real runs. For example, Haiku tried pytest 1.44× per session, while Sonnet never tried npm test. The simulator is for sample-efficiency curves and threshold sweeps, and is never a release gate on its own.
  • Public trajectories (SWE-Gym, SWE-smith, OpenHands, nebius) through a new swe.rs importer: many tasks per repository, real conventions (django's runtests.py), no inference cost. Check each licence; raw dumps stay out of git.

Budget tiers: pull requests $0 (simulator + replay) · nightly ≤ $5 · weekly regression ≤ $150 · quarterly corpus of about 200 sandboxes, $1.5–3k.

B · Consumer training beyond history

Skill → reflex ships as a separate binary, adage-train. The adage binary that hooks call keeps its promise that it never executes anything. adage-train drives the user's own harness, headless, under that harness's permissions and sandbox. It refuses to run inside an agent session, and no hook, config key or track can start it.

adage-train plan --from .claude/skills/db-migrations/SKILL.md     # free: extracted claims + generated tasks + cost estimate
adage-train run  --from SKILL.md|CONTRIBUTING.md|Makefile|ci.yml|runbook.md \
    --harness claude-code --model claude-haiku-4-5 --sessions 12 --validate 12 \
    --budget 5.00 --max-turns 25 [--oracle trajectory|tests] [--container docker] --execute
adage-train report <run>      # per claim: compiled → route · never exercised · contradicted · unsafe

How a run works

  1. Claim extraction. Deterministic, no LLM: commands, paths and globs from code blocks, plus "after / before / instead of" sentences. Each claim is typed as verify, regenerate-after, lookup, avoid or environment. Commands above regenerate are reported as unsafe and never exercised.
  2. Seeded task generation for each claim: mutation edits on matching globs and break-fix mutations. About 70% of prompts are implicit (they never name the skill), and ≥ 25% are control tasks.
  3. Isolation. A git clone --local with no origin, an isolated harness config, a scrubbed environment, and the harness sandbox with network off. Web and Agent tools are denied.
  4. Exploration sessions (skill loaded, no hooks) are mined as synthetic. Validation runs on held-out seeds in three arms: baseline, skill-in-context, reflex.
  5. Acceptance: followed ≥ 70%, reflex arm non-inferior to skill arm within 10 points, turns and cost no worse.

Other training modes

  • From repository files (free): Makefile rules, package.json scripts, lockfiles, pyproject, Cargo workspace, CI steps, AGENTS.md/CLAUDE.md code blocks. These produce declared facts that bind instinct slots and draft candidate routes.
  • adage teach (explicit authoring) and adage record --session (a demonstration).
  • Corrections: a directive, then the user's next prompt names a command, then that command succeeds. This yields a proposal only, because prompt text is untrusted. Add adage review replace.
  • CI logs from the user's own gh run view --log export: missed-obligation evidence and dead-end candidates.
  • Instinct packs, distributed like shared tracks: signed, installed at probation.
  • A by-product worth selling: skill linting with evidence. "Your skill says npm test; it failed in 11/12 runs; npm run check worked."

C · Instincts to ship

Mechanics:

  • Instincts live as data in a new crates/adage-instincts. The learner binds them per repository, so the runtime stays a pure function of the index and determinism holds.
  • A bound id equals the id the miner would derive for the same behaviour, so the index's existing "learned wins" dedup lets a local reflex override the instinct automatically.
  • For new repositories, the first bind is triggered at SessionStart.
  • The wrapper text changes by provenance. render.rs:55 says "Learned by Adage from this repository's earlier agent sessions," which would be false for an instinct.

Protocol (pre-registered)

Design

  • Split: per repo, by base_commit date. The first ~50% are train and the last ~50% test, with a 2–3 instance buffer between them. A leave-repo-out control separates repository learning from generic effects.
  • No leakage: Adage never sees gold patches, FAIL_TO_PASS lists or hints. An automatic scan checks directives against test-set gold paths. Web tools are off in every arm.
  • Arms: identical model, CLI version, turns and timeouts, interleaved and seeded. Other memory is off in every arm.
  • Strong baselines: AGENTS.md generated from the same train transcripts, and in-context notes (CL-Bench's strongest baseline). Without these, reviewers will call the result "just memory."
  • Clean patches: hook files never enter the worktree (.codex/ and .adage/ would pollute git diff).

Statistics and power

  • The pairing unit is the task. CIs come from a cluster bootstrap over repos, then tasks. Holm correction across the primary metrics: resolve rate, cost, turns.
  • Detecting −10% cost or turns needs ~170 pairs; −15% needs ~75. Efficiency is where Adage can win credibly.
  • A +5pp resolve change needs ~630 pairs; +10pp needs ~160. SWE-bench Pro's ~320 test tasks can detect about 6–7pp.
  • Guardrails accumulate as anytime-valid confidence sequences across nightly runs, as Design Spec already calls for.
  • A pilot of 20 tasks measures the discordance rate and SD, then n is fixed before the main run.

Objective and guardrails the optimizer runs against

Hard guardrails (infeasible if violated)

  • 0 unsafe directives; 0 fast-path mismatches; 100% fidelity
  • Hook p95 within the Architecture budget with 20% headroom
  • L1 harm (a followed wrong directive that led to failure) ≤ cap
  • L2 lower CI of Δpass ≥ −5 points, accumulated across nights
  • L4b no Terminal-Bench regression

Objective

J₀ = turns saved@window − λfp·false directives − λcal·ECE + λgt·route F1

J₂ = −log(TFE ratio) − 0.5·log(cost ratio), task-cluster bootstrap, with a restricted mean for censored runs.

Track G · Graph and prediction engine v2

docs/tracks/track-g-graph-engine.md

The learner stops knowing route kinds. Each session becomes a small event graph. Its nodes are prompts, commands, files, outputs, failures and outcomes, and each carries an embedding. Its edges are follows, value flows into, reads/writes, fails with and recovers with. Learning crawls these graphs for common subgraphs, and each useful one becomes a reflex. Its earliest nodes are the trigger, its later nodes the continuation, and its value-flow edges the typed inputs.

How the mining works

  • Prototypes. Nodes are embedded and clustered per type, deterministically (exact kNN + Louvain), so mining runs over labels rather than doing fuzzy matching during the search. A label hierarchy (exact ⊂ prototype ⊂ coarse ⊂ head) provides the "softness".
  • Algorithm. PrefixSpan-style episode growth over time-ordered session graphs, rooted at things that could be delivered, keeping closed patterns only. General graph mining (gSpan, GraMi) is rejected: sessions are nearly sequences, so the order is already known.
  • Frequent ≠ useful. Patterns are scored by confidence (a Beta posterior that falls back to shorter contexts), lift over background (which removes ls/cat), value per turn, and causal lift from knockouts. An MDL cover picks among overlapping patterns.
  • Embeddings widen triggers, never actions. A continuation must compile to one dominant concrete command (≥ 80% of support).

Kinds survive only at the output boundary

A deterministic compiler maps each reflex to one of six delivery shapes: run, avoid, read-batch, obligation, sequence, advise. Each has a fixed template, typed input contracts, effect ceilings and interlocking.

Parity test. Today's five kinds must fall out as special cases: prompt→lookup is a value-flow edge, dead end is fail→recover, finish line is last(edit)→regenerate. The new engine must also learn scope, env_sync and multi-step sequence conventions from generated sandboxes with no learner code change.

Learned input types (G1) replace the hard-coded [A-Z][A-Z0-9]{0,9}-\d{1,7} detector. Tokens that flow from prompts or earlier output into later commands are generalised by anti-unification and MDL into anchored, bounded contracts, covering #482, UUIDs, ops/412 and branch names.

Track C · Compiled skills and the packaged artifact

docs/tracks/track-c-compiled-skills.md

Instincts and reflexes are compiled skills: inference turned into signed, content-addressed, reusable artifacts that take typed inputs and may execute. An instinct is a portable compiled skill; its applicability is a detector over repository files. A reflex is repo-bound; its applicability is the repository's identity or a structural fingerprint.

Closure of the pack

  • Contents. The route graph with typed inputs and outputs, the applicability rule, tool and OS requirements, evidence by origin, optional bench attestations, a CLOSURE listing, and an sshsig signature in a new adage-pack namespace.
  • Scripts, three levels. L-none: only known commands. L-ref: a repository path plus a SHA-256, re-checked at run time. L-vendor: the bytes are embedded; this needs a signed pack and explicit approval, and is never automatic.
  • Closure rules. A command that names a repository script without pinning it is refused. Bytes nothing references are refused. No dependencies between packs in v1.
  • Never in a pack: approvals, spools, prompts, bound values, outputs.

Execution levels and approval

  • E0 directive, as today. E1 prefetch: run an approved read-only route and inject typed, fenced output. E2 routes as MCP tools, so the harness asks permission per call. E3 actions: staged, checked against declared outputs, then applied.
  • A separate adage-exec binary. The hook binary keeps "spawns nothing", checkable by grep in CI.
  • The sandbox is the boundary, not classification: Landlock + seccomp or bubblewrap on Linux; sandbox-exec on macOS; Windows stays at E0.
  • Approvals are local. Each is keyed by hashes of the argv, inputs, scripts, effect, level and sandbox profile, and lapses on any change. Auto-approval only for inert, read-only, known commands, after gate G3.

Milestones: C0 format · C1 distribute and bind · C2 execution core and sandbox · C3 E1 prefetch · C4 E2 MCP (needs Track G's learned input types) · C5 actions, vendoring, attestations. About 13–15 weeks. Gates before any default changes: 0 sandbox escapes; E1 saves ≥ 0.5 turns per triggered session with the lower CI bound above 0; injection harm no worse than the agent reading the same output itself.

Decisions for you

each with a recommendation

1. Amend "Adage never executes anything"?

Skill → reflex needs something to drive agent sessions. Recommend: a separate, optional adage-train binary that drives the user's own harness, sandboxed, at a terminal only. The adage binary and plugin keep the promise word for word. Design principle 1, non-goals, Q4 and F10 get updated to match.

2. How to handle the current README headline

Recommend: keep the numbers, add a one-line caveat now (same-task rounds, fixed arm order, shared auto-memory), and replace them after the Phase 0 re-run on a clean split. Credibility with the benchmark audience depends on getting this right first.

3. Instincts on by default?

Recommend: the core P0 pack on by default at yellow, reactive where possible, subject to holdout, and auto-retiring. Environment-effect instincts (U7, U10) need a one-time pack-level approval in adage init.

4. External benchmark budget

About $2–5k for the SWE-bench Pro headline across two models, plus $1–3k for breadth, plus ~$13 a night for L2. Recommend: approve the L3 dev-set spend (~$500) now, and decide on L4 after the 20-task pilot measures real per-trial cost.

5. Public trajectory data

Recommend: use it for internal tuning only. Keep raw dumps in a team bucket, and commit only redacted derived datasets whose licences allow it, with licence and source recorded in each manifest.
