# adage-term

Adage's terminal design system: generated colour tokens, terminal capability detection, semantic
roles resolved into `anstyle` (and optionally ratatui) styles, and the output grammar every
command prints through. Nothing here runs on the hook path.

## Where it sits

- Layer 0 in `xtask/src/layers.rs` (kernel primitives). It links no workspace crate; external
  dependencies are anstyle, anstream, unicode-width and, behind the `ratatui` feature,
  ratatui-core.
- Linked (`[dependencies]`) by `adage-cli` (with `features = ["ratatui"]`, for `adage watch`,
  `adage ui` and `adage init`) and `adage-app` (default features).
- No `FORBIDDEN` edge names it. It must stay free of workspace dependencies: it is about how text
  looks, not what it says.

## What's inside

- `tokens`: generated by `cargo xtask tokens` from `design/tokens/adage.tokens.json`; never
  edited by hand. `Swatch` constants (`ACCENT_BASE`, `ACCENT_SOFT`, `COST`, `INK_1..INK_3`,
  `LAMP_FIRE`, `LAMP_PRIME`, `LAMP_INHIBIT`) and the `glyph` and `font` submodules.
- `color`: `Rgb`, `Ansi16`, `Swatch { night, day, night_256, day_256, ansi16 }`.
- `caps`: `Level` (None, Ansi16, Ansi256, TrueColor) and `Caps { level, unicode, day, hyperlinks,
  effects }` with `plain()`, `stdout()`, `stderr()` and the testable `from_env(env, is_tty)`.
- `theme`: `Role` (Ink, Ink2, Ink3, Accent, Command, Fire, Prime, Inhibit, Cost), `Strength`
  (Fire, Prime, Inhibit; `word`, `role`, `parse`), `Glyph`, `Fg`, `Resolved`, and `Theme` with
  `new`, `plain`, `stdout`, `stderr`, `resolve`, `style` (anstyle), `tui` (feature `ratatui`),
  `glyph`, `strength_label`.
- `out`: `Line` (a builder: `push`, `bold`, `text`, `quiet`, `faint`, `cmd`, `sep`, `glyph`,
  `strength`, `pad_to`, `render`, `plain`), `KEY_WIDTH`, and `Out<W>` with `stdout`, `stderr`,
  `raw`, `header`, `kv`, `section`, `line`, `blank`, `next`, `also`, `done`, `note`, `warn`,
  `error`, `error_items`, `flush`.

## How it connects

- No traits. Input is the environment, read once by `Caps::from_env` in this precedence:
  `ADAGE_COLOR`, then `NO_COLOR`, then `CLICOLOR_FORCE`/`FORCE_COLOR`, then whether the stream is
  a terminal and `TERM`/`COLORTERM`; `ADAGE_THEME` or `COLORFGBG` pick a light ground.
- Output is styled text through `anstream` (`Out::stdout`/`stderr`) or ratatui styles
  (`Theme::tui`). Call sites in `adage-cli` and `adage_app::words` ask for a `Role` or a
  `Strength`, never a colour.
- The same token file drives the web map: `cargo xtask tokens` writes both `src/tokens.rs` here
  and `design/build/tokens.css`. The rules the roles follow are in
  [docs/design/style.md](../../docs/design/style.md).

## Changing it

- Run `cargo test -p adage-term` and `cargo test -p adage-term --features ratatui` (`Theme::tui`
  only compiles with the feature, and `adage-cli` enables it). Then `cargo test -p adage-cli`,
  whose `ui/tests.rs` snapshots whole frames, and `cargo test -p adage-app`.
- Snapshots are insta files in `src/snapshots/` (`status_plain`, `status_ascii`,
  `errors_show_cause_and_help`). Review with `cargo insta review` or `INSTA_UPDATE=always`; never
  commit a `.snap.new` ([docs/testing.md](../../docs/testing.md)).
- To change a colour or glyph, edit `design/tokens/adage.tokens.json` and run
  `cargo xtask tokens`. `cargo test -p xtask` (`the_committed_tokens_are_current`) fails while
  `tokens.rs` or `tokens.css` is stale, and also checks the palette's contrast. This crate's own
  tests do not read `design/`, which is why `design/` is declared in `READS` for `xtask` only.
- Invariants the tests hold: `Role::Ink` never gets a colour (`body_text_never_gets_a_colour`);
  at 16 colours roles map to the user's ANSI theme; with no colour, strength is spelled out and
  only bold and dim remain; nothing paints a background; coloured and plain renderings of a
  `Line` occupy the same columns (`colour_columns_line_up_with_plain_columns`, which is why
  `pad_to` measures with `unicode-width`).
- `Caps::plain()` keeps `unicode: true`, so plain snapshots contain UTF-8 glyphs; the ASCII
  fallbacks are exercised by `status_ascii`. Every `Glyph` needs a one-column glyph and an ASCII
  fallback (`newer_concepts_have_one_column_glyphs_and_ascii_fallbacks`).
- `Strength::parse` also accepts the schema's `green`/`yellow`/`red`; keep that when renaming.
- Every command ends with `Out::next`; add new output shapes to `out` rather than printing with
  `println!` in a front end.
