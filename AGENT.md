# Adage: working in this repository

Adage reads the transcripts coding agents leave behind (Claude Code, Codex, OpenCode), finds the
procedures they keep repeating, and compiles them into reflexes: small, deterministic responses
delivered to the agent through harness hooks, with the evidence attached. The flow is: traces on
disk are ingested into one canonical `Session` model (`adage-ingest` → `adage-trace`); the learning
engine mines those sessions into tracks and compiles an index (`adage-graph`, `adage-learn`); at
each hook event the runtime matches the index against the live session and decides what to say
(`adage-runtime`, `adage-hook`); the `adage` binary, the TUI and `adage map` read the same store
through `adage-app`. Running commands is a separate, opt-in binary (`adage-exec`). The component
map, the ports and the layering rules are in [docs/architecture.md](docs/architecture.md); every
statement below points at a file that enforces or documents it.

## Map of the repository

Top level:

- `crates/` — the Rust workspace members (`Cargo.toml`: `members = ["crates/*", "xtask"]`). Each
  crate has its own `AGENT.md` describing its role, boundaries and tests; read it before editing.
- `xtask/` — repository tasks (`cargo xtask …`) and the architecture guards that `cargo test -p xtask`
  runs: `layers.rs`, `affected.rs`, `hygiene.rs`, `suites.rs`.
- `docs/` — the user and design documentation; `docs/architecture.md` and `docs/testing.md` are the
  current references for structure and tests.
- `evals/` — Python eval suites, datasets, baselines, sandbox repositories and curated evidence
  (`evals/README.md`). `demo/` runs real headless agents on a sandbox repository (paid; not in CI).
- `web/map` — the React app `adage map` serves, embedded into the binary. `web/site` — the public site.
- `plugin/` — the Claude Code plugins (`claude-code`, `claude-code-exec`) and the OpenCode plugin;
  `npm/` — the npm launcher; `packs/` — the built-in instinct packs; `sim/fixtures/` — harness
  histories generated by `adage-sim`; `design/` — design tokens (`cargo xtask tokens`);
  `scripts/` — plugin checks, `cross-check.sh`, `notice.sh`; `spikes/` and `research/` — records.

Crates by layer, exactly as `xtask/src/layers.rs` assigns them (a crate links only strictly lower
layers):

| Layer | Crates | Role |
| --- | --- | --- |
| 0 | `adage-core`, `adage-sign`, `adage-term`, `adage-store`, `adage-sim`, `xtask` | Kernel primitives: shell normaliser and command table, sshsig signing, terminal design system, state files and spools under `$ADAGE_HOME`, the harness simulator |
| 1 | `adage-trace`, `adage-intent` | The canonical trace model (`Call`, `Event`, `Session`, `Harness`); the intent model and bundled embedding model |
| 2 | `adage-tracks` | The reflex model (tracks, the compiled index, reviews, proposals) and the matching primitives the learner and runtime share |
| 3 | `adage-ingest`, `adage-graph`, `adage-runtime`, `adage-instincts`, `adage-safety` | Engines: ingestion, the graph learner, hook-time decisions, instincts, the independent safety oracle. Siblings never link each other |
| 4 | `adage-pack` | Packs: validation, closure, digest, and the record of how instincts were bound |
| 5 | `adage-learn` | Learning orchestration: ingest → mine → write tracks and the index through a `Store` |
| 6 | `adage-hook`, `adage-eval` | The live hook pipeline shared by `adage` and `adage-exec`; offline evaluation |
| 7 | `adage-exec` | Execution: approvals, policy, the OS sandbox |
| 8 | `adage-app` | The application layer: review decisions, the map's read model, savings, one `Reflex` rendering |
| 9 | `adage-cli`, `adage-train` | Binaries: argument parsing, rendering, the TUI, the `adage map` HTTP server; skill compilation |

## Architecture standards

- **Layering is a test.** `LAYERS` and `FORBIDDEN` in `xtask/src/layers.rs` are checked by
  `the_workspace_respects_its_layers` on every `cargo test -p xtask`, which CI always runs. A new
  crate must be given a layer there or the test fails. Dev-dependencies are exempt. `EXCEPTIONS` is
  empty today and may only shrink: a listed violation that disappears also fails the test.
- **Forbidden edges beyond the layers** (`FORBIDDEN`): `adage-ingest` never links `adage-tracks`
  or `adage-store`; `adage-runtime` never links `adage-store` ("the runtime decides; the hook does
  the I/O"); `adage-learn` never links `adage-runtime`; `adage-hook` never links `adage-learn`;
  `adage-exec` never links `adage-eval` or `adage-learn`.
- **One canonical model.** `adage-trace` owns `Call`, `Event`, `Session` and `Harness`. Each
  harness is translated into it once, at the edge (`adage-hook::harness::Adapter` for live payloads,
  `adage-ingest::{claude,codex,opencode}` for histories); nothing past the edge knows a harness's
  format, and behaviour differs by `Harness` capability, not by comparing names (docs/architecture.md).
- **I/O goes through ports.** Ingestion: `TraceSource` (`crates/adage-ingest/src/source.rs`),
  `Format` (`format.rs`, sniffed from the first bytes), `Locator` (`locate.rs`; `AsRecorded`
  decodes traces from another machine with no local checkout). Learning: every read of earlier
  results and every write goes through `adage_learn::store::Store` (`crates/adage-learn/src/store.rs`);
  `Files` is `$ADAGE_HOME`, tests use an in-memory store. Runtime: `decide(ctx, state, event)` is
  the single entry point; everything it reads of the working tree goes through the `Checkout` port
  on `Ctx` (`crates/adage-runtime/src/checkout.rs`: `Disk` in the hook, `Unread` for replays), and
  its switches are fields of `Policy` on `Ctx` (`crates/adage-runtime/src/policy.rs`), never hidden
  globals. Add a new input to one of these traits rather than reaching for the filesystem.
- **The live hook path fails open and spawns only what is listed.** `adage_hook::run` returns `Ok(None)` or
  `Err`, and the caller prints nothing in either case, recording the error in `$ADAGE_HOME/fail-open.log`
  (`crates/adage-hook/src/lib.rs`, `failopen.rs`). CONTRIBUTING.md: anything on the hook path exits 0
  and prints nothing on any error. `crates/adage-exec/tests/no_spawn.rs` scans the `src/` of
  `adage-cli`, `adage-hook`, `adage-runtime`, `adage-store`, `adage-tracks` and `adage-learn` for
  `Command::new`; every use must be in its `ALLOWED` list with a reason (the hook's one is
  `autolearn.rs` starting `adage condition` in the background). No hook or learner uses the
  network (README, "Safe by default").
- **Learning is deterministic.** `adage_graph::learn(sessions, params)` is pure: the same sessions
  give the same bytes whatever the input order or thread count
  (`crates/adage-graph/tests/determinism.rs`). Keep new mining logic free of wall-clock, hash-map
  iteration order and machine state.
- **One rendering of a reflex.** `adage_app::reflex::Reflex` (`crates/adage-app/src/reflex.rs`) is
  the JSON every surface emits (`status --json`, `review --json`, the map's `/api/v1/graph`), each
  adding only its own fields; `every_surface_renders_a_reflex_the_same_way` in
  `crates/adage-cli/tests/graph.rs` checks it. Promotion rules live in `adage_app::review`, which
  takes the tracks lock; the CLI keeps argument parsing and terminal rendering.
- **Where new code goes.** Decoding a new history format: `adage-ingest` (a `Format`). Mining or
  scoring: `adage-graph`. What to say at an event: `adage-runtime`. Reading or writing
  `$ADAGE_HOME`: `adage-store`, `adage-tracks` or the learner's `Store`. Operations a front end
  calls: `adage-app`. Terminal output: through `adage-term`. Platform differences go behind
  `cfg(unix)` / `cfg(windows)`, and Unix-only tests are `#[cfg(unix)]` (CONTRIBUTING.md).

## Building

Stable Rust and a C compiler (tree-sitter); Node 22 or later for the plugin, npm and web tests.
`Cargo.lock` is committed, so build and test with `--locked`.

```bash
cargo build --workspace --locked
cargo build --release --locked -p adage-cli -p adage-exec -p adage-train   # target/release/{adage,adage-exec,adage-train}
plugin/build.sh                                                            # release build staged into the Claude Code plugin, with SHA256SUMS
```

The release profile (`Cargo.toml`) is `opt-level = 3`, `lto = true`, `codegen-units = 1`,
`strip = true`, `panic = "unwind"`; `profile.dist` inherits it for the release workflow. Latency
budgets are checked only on release builds (CONTRIBUTING.md, the startup gate). The `cargo xtask`
alias is in `.cargo/config.toml`; `cargo xtask tokens` regenerates `crates/adage-term/src/tokens.rs`
and `design/build/tokens.css` from `design/tokens/adage.tokens.json` (`--check` fails when stale).

The map front end lives in `web/map` (pnpm 10, Node 22): `pnpm install --frozen-lockfile`, then
`pnpm build`. `pnpm assets` (build plus `scripts/embed.mjs`) writes the compressed page into
`crates/adage-cli/assets/map/` and generates `crates/adage-cli/src/map/assets_list.rs`; commit both.
The embed is deterministic and has a 400 KB brotli budget for the page; `pnpm drift` rebuilds and
fails if the committed copy differs, which CI's `design` job runs. Those assets are the one place
`xtask/src/hygiene.rs` allows files over its size limit for the map.

Disk space: the workspace's debug test build is large. CI sets `CARGO_PROFILE_DEV_DEBUG: line-tables-only`
and frees space on the Linux runner before building (`.github/workflows/ci.yml`); set the same
variable locally if linking test binaries fills a small disk.

## Testing standards

Before pushing, run what CI runs on a pull request (`.github/workflows/ci.yml`, CONTRIBUTING.md):

```bash
cargo fmt --all --check                                        # rustfmt.toml: max_width = 120
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --locked -p xtask                                   # layers, affected-path declarations, hygiene, suites: always
cargo test --locked -p adage-exec --test no_spawn              # always
cargo xtask affected                                           # the packages your change can affect (against origin/main)
cargo test --locked -p <each affected package>                 # or cargo test --workspace --locked
cargo xtask test python [<suite>]                              # the Python suites in xtask/src/suites.rs, when evals/ changed
```

When `web/map` is touched: `pnpm typecheck`, `pnpm test` (vitest), `pnpm drift` and `pnpm test:e2e`
(Playwright with axe; it builds `target/debug/adage` and starts `adage map` itself, see
`web/map/playwright.config.ts`). `web/site` has `pnpm typecheck`, `pnpm test:api`, `pnpm test:evidence`
and `pnpm test:e2e`. Plugin and launcher checks: `node npm/test/launcher.test.mjs`,
`plugin/test/session-start.test.sh`, `node scripts/check-plugin.mjs`, `cargo deny check`.

How CI picks packages (`xtask/src/affected.rs`): a package is affected when a file in its directory
changed, when a path it reads outside every package changed (`READS`), or when a package it depends
on in any role is affected. A changed path that is in no package, not in `READS` and not in `INERT`
(the lockfile, `Cargo.toml`, CI itself, a new directory) tests everything. A test that reads a file
outside its crate must be declared in `READS`; `every_path_a_crate_reads_is_declared` scans every
crate's sources and fails on an undeclared read into an inert directory. `adage-eval`'s gates run in
`evals.yml` (weekly and on dispatch), not on pull requests.

Where tests live (`docs/testing.md`):

- Unit tests in `#[cfg(test)]` beside the module (large ones in `src/tests/`, one file per
  topic); integration tests in `crates/<crate>/tests/*.rs`; shared helpers in `tests/common/mod.rs`
  of the crate that needs them.
- Inputs are fixtures: `crates/<crate>/tests/fixtures/` for one crate; shared inputs have one home
  each (`sim/fixtures/`, `evals/datasets/`, `evals/sandboxes/`). `cargo run -p adage-sim`
  regenerates `sim/fixtures/`, and `adage-sim`'s tests fail when they drift.
- Expected outputs are reviewed like code: golden `.txt` files under `tests/golden/` (re-bless with
  `ADAGE_BLESS=1`), insta snapshots under `snapshots/` (`cargo insta review`; `*.snap.new` is never
  committed), or the `expect` of a table-driven case in `tests/cases/*.json`. "Golden" always means
  an expected output, never an input.
- Each component is tested through its own crate: decoders from bytes (`adage-ingest`), `decide()`
  as a function of index, state, event, policy and checkout (`adage-runtime/src/tests/`), the
  learner over fixtures through ingestion, `adage-app` against a temporary `ADAGE_HOME`, the binary
  end to end in `adage-cli/tests/`.
- Python suites keep `test_*.py` beside the modules they test and use `unittest`; each suite is
  declared in `xtask/src/suites.rs` (`PYTHON`), and a tracked test file in no suite fails
  `every_python_test_belongs_to_a_suite`.
- Live evals (`demo/`, `evals/live/`, `evals/reflex-proof/harness/`) call a paid model API and are
  never in CI: run them by hand when a change affects what directives say or when, and report the
  numbers in the pull request.

Data policy for eval output (`evals/README.md`, enforced by `xtask/src/hygiene.rs`):

- **Fixtures** (inputs a test reads) are tracked, live under the test's directory or `evals/datasets/`,
  and are declared in `READS`.
- **Evidence** (a study's curated result: `README.md`, `FINDINGS.md`, `RESULT.json`, small summary
  tables) is tracked beside the study's code.
- **Raw run output** (per-session logs, transcripts, `ADAGE_HOME` archives, frozen source, rendered
  HTML) is never committed. `.gitignore` ignores `evals/**/results/`, `demo/results/` and `*.log`,
  so committing one takes a deliberate `git add -f`. The hygiene test refuses tracked files over
  1 MiB (`MAX_BYTES`) and any `.log`, `.err`, `.tgz`, `.tar`, `.gz` or `.zip` unless listed in
  `ALLOWED` with the reason; an `ALLOWED` entry no file uses also fails, so the list only shrinks.
- Some archived runs are test fixtures in place (`evals/reflex-proof/harness/results/<run>/`,
  `evals/showcase/live/`). They stay committed where they are, whole; pruning one breaks its tests.

Never skip, ignore or weaken a test to get a green run. CI checks that the OpenCode plugin test
actually ran under node rather than being skipped (`ci.yml`), and the guards above fail on a listed
exception that no longer exists, so lists of exceptions are not a place to park a failure. Fix the
change or the test, or declare the new read, layer or suite in the xtask table it belongs to.

## Commits and pull requests

- **Every commit carries a DCO sign-off** (`git commit -s`, giving `Signed-off-by: Name <email>`).
  The `dco` job in `.github/workflows/ci.yml` checks every non-merge commit of a pull request and
  fails on a missing line (CONTRIBUTING.md, decision D2). There is no CLA; contributions are under
  Apache-2.0.
- **Record user-visible changes in `CHANGELOG.md`**, in the top section (`## 0.1.0 - Unreleased`,
  Keep a Changelog format). Its text becomes the GitHub Release notes, so write it for users.
- **Keep changes focused, with tests.** A pull request tests only the affected packages, so a
  change to shared fixtures or to a crate low in the layers reruns everything that depends on it;
  that is expected.
- **Keep eval data out of pull requests** unless a test needs it. New raw output does not belong in
  git at all; a new fixture goes under the test's directory or `evals/datasets/` and into `READS`;
  a new large or log-like file that a test must read needs an `ALLOWED` entry in
  `xtask/src/hygiene.rs` with its reason. Paid eval results go in the pull request description as
  numbers, not as files.
- **Dependencies** must carry a license on the allow list in `deny.toml` (permissive only);
  `cargo deny check` runs in CI and `scripts/notice.sh` regenerates `NOTICE`.
- **Version bumps** touch `Cargo.toml` (`[workspace.package]`), `plugin/claude-code/.claude-plugin/plugin.json`
  and `.claude-plugin/marketplace.json` together; `scripts/check-plugin.mjs` fails CI until they agree.
