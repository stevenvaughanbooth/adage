How we tested

{{heldout:headline}}

Adage learns your repository's recurring work and gives your agent what it would otherwise go looking for. Adage saves model calls by handling learned reflexes and instincts on your CPU, so the agent spends its calls on the actual problem.

The question we test

Can Adage handle predictable steps on your CPU so the agent needs fewer model calls, without hurting correctness?

It is strongest on the work a repository repeats. A novel task still needs the model's reasoning, and Adage leaves that alone.

What we tested

Same task, with and without. Rules first, results after.

We gave {{ev:heldout:study.model}} {{ev:heldout:study.tasks.length}} new coding tasks on {{ev:heldout:study.repository}}, a real open-source library, each run {{ev:heldout:study.repetitions}} times three ways: the agent alone, the agent with Adage in advisory mode (the default), and with execution mode switched on (opt-in). Hidden tests graded every result. {{ev:heldout:study.sessions}} sessions in all, safety controls included, and every one counted.

  1. 01

    Paired comparisons

    Every task runs as a paired comparison, with Adage and without it: same repository, same prompt, a fresh checkout each time. Comparing pairs keeps a hard task from looking like a slow tool.

  2. 02

    Hidden tests

    The agent never sees the tests that grade its work. Fewer calls only count if the code is still right.

  3. 03

    Safety controls

    First come runs where checking again is the right move: a failing test, a later edit, a changed config, a broader change, an explicit request to rerun. Adage must never let the agent skip necessary work. One miss stops the study.

  4. 04

    A person approves, a sandbox runs

    In execution mode, Adage runs only the exact command a person approved, inside an operating-system sandbox, on the CPU. If the command or its environment changes, the approval stops matching and nothing runs. Advisory mode runs nothing at all.

  5. 05

    Pass rules written first

    The line a result must clear is written down and committed before the first session, and never moved after.

  6. 06

    Every attempt kept

    Failures and stopped studies stay in the record with their costs. Nothing is rerun to get a better number.

What “held-out” means

We tuned Adage on a development task, so a good score there proves little. Held-out tasks are new tasks, written and frozen before any result was read, and never used for tuning. Their prompts are what a person would type: no work order, no supplied tests, no instruction to run them. They answer the real question: does it work on the next task, the one nobody tuned for?

More detail: how a session is counted

Model requests are counted from Claude Code's own debug log: one line per request it sends, retries included, since they are billed too. Each session is cross-checked against the request ids in its output stream; a gap that logged API errors do not explain makes the session unverified, and its whole paired block leaves the comparison, for every arm alike.

The comparisons are ratios of total requests, with Adage over alone, across the paired blocks. Their one-sided 95% upper bound comes from a bootstrap that resamples blocks within each task, 20,000 draws, with a fixed seed; the line to clear is 0.90. The study's pass/fail test was registered for execution mode: its upper bound at most 0.90, and its hidden-test passes at least the agent alone's minus one, plus a set of safety criteria. The advisory comparison was registered to be reported beside it, with the same statistics.

Censoring works against Adage. A session that stops early (its turn limit, its budget, the clock) is a quality failure in every arm, and only execution mode's is raised to 60 requests.

The two modes. Advisory mode is what Adage does by default: instincts from the repository's own files, a procedure card that says where the files stand right now, and learned advice at the right moment. Nothing runs on the agent's behalf. Execution mode adds person-approved test runs on your CPU and a finish-line check. Cost is the API list price.

Limits and what's next

What this shows, and what we test next.

The limits

  • One repository, one model. These tasks were on Marshmallow, with Claude Haiku 4.5. Other repositories and other models are next.
  • Learned from this repository. Adage learned from earlier sessions here, some of them guided; the gain comes from work a repository repeats.
  • Model calls, not GPUs. We count model requests, tokens and API cost. GPU use and energy are not measured.
  • Execution mode is experimental. It saved more calls, but has not yet shown it keeps quality, so it stays opt-in.

What we test next

  • Expensive to cheap. Learn from sessions with a strong model, then see whether a cheaper model, with Adage, can do the same work.
  • More repositories. Including one the learning pipeline has never seen.
  • Execution mode's quality bar. A new registered test before it is anything more than experimental.

More detail: the held-out commands

From evals/reflex-proof/harness, with $H the frozen held-out root. live is the only paid step; it dispatches in the frozen order, controls first, and stops on any lapse. The handoff has the full sequence.

python3 heldout_cohort.py prepare $H        # offline: fresh checkouts, read-only runtime
python3 heldout_cohort.py verify-grants $H  # a person issued exactly the reviewed approvals
python3 heldout_cohort.py live $H           # paid: 65 sessions, one at a time
python3 heldout_cohort.py report $H         # the registered analysis and its decision record
