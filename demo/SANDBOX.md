# Demo sandbox — specification

A small, realistic repository — **acme-billing** — with conventions a coding agent cannot guess and
must otherwise discover. Real headless Claude Code agents work tasks in fresh copies of it, with
and without Adage.

## Constraints

- **Python 3.9 standard library only.** No pip installs. Tests use `unittest`. The system
  `python3` is 3.9.6; there is no `pytest`.
- Everything is generated by `demo/sandbox/generate.py <out_dir>`, deterministic, and fast
  (< 1 s). The generated directory is a git repository with one initial commit.
- Every script is harmless: reads and writes only inside the sandbox.

## The three conventions

1. **Work items live only in the tracker.** `scripts/wi-lookup <ID> [--json]` prints the work item
   from `.tracker/items.json`: `id`, `title`, `description`, `linked_files`, `acceptance`. Task
   prompts name only the ID ("Pick up W-2042 and get it done."). The README says only that work items
   are in "the internal tracker".
2. **Tests run through make.** `make test` sets `ACME_ENV=test` and runs
   `python3 -m unittest discover -s tests`. Running unittest directly fails immediately from
   `tests/__init__.py` with: `RuntimeError: ACME_ENV is not set — run tests with 'make test'`.
   (`pytest` is simply not installed.) This is the **dead end**.
3. **Generated models.** `schema/*.json` define records (fields with type and default).
   `make gen` runs `tools/gen.py`, which writes `acme/generated/models.py` (dataclasses). The
   generated file is committed. `make ci` runs a staleness check (regenerate to a temp file and
   compare) and fails with `generated models are stale — run 'make gen'` if they differ. Changing a
   schema without `make gen` breaks CI. This is the **finish-line obligation**.

## Layout

```text
acme-billing/
├── README.md              two short paragraphs; mentions "the internal tracker" and the Makefile
├── Makefile               gen · test · ci · lint (lint = python3 -m py_compile over acme/)
├── scripts/wi-lookup      executable Python
├── .tracker/items.json    all work items (training + held-out)
├── schema/invoice.json    fields: id, customer_id, amount_cents, tax_region, discount_pct, …
├── schema/customer.json   fields: id, name, email, region, …
├── tools/gen.py           schema → dataclasses
├── acme/__init__.py
├── acme/billing.py        totals, tax by region, discounts, late fees
├── acme/customers.py      validation, lookup helpers
├── acme/generated/__init__.py
├── acme/generated/models.py
└── tests/
    ├── __init__.py        the ACME_ENV guard
    ├── test_billing.py
    └── test_customers.py
```

## Work items

Twelve items, each with a **hidden check**: an extra `unittest` file kept outside the sandbox
(`demo/sandbox/hidden/test_<ID>.py`) and copied in only when scoring. Seeded bugs are real, small,
and located in the linked files. Mix per split:

| Split | IDs | Kinds |
| --- | --- | --- |
| Training | W-1041 … W-1046 | 4 code fixes (billing/customers), 2 schema changes that require `make gen` |
| Held-out | W-2041 … W-2046 | 4 code fixes, 2 schema changes — different bugs and fields from training |

Examples of the kind of work:

- Discount rounding uses floor instead of banker's rounding for half-cents.
- EU tax region uses the wrong rate.
- Late fee applied on the due date instead of after it.
- Email validation accepts addresses without a domain dot.
- Add `currency` (string, default "USD") to the invoice schema and use it in `format_invoice`.
- Add `due_days` (int, default 30) to the invoice schema and use it in `due_date`.

Each work item's `description` states the problem as a user would. `linked_files` lists the one or
two files that need to change. `acceptance` states the expected behaviour precisely enough that the
hidden test is fair.

## Scoring

`demo/sandbox/score.py <sandbox_dir> <ID>`:

1. Copies `hidden/test_<ID>.py` into `tests/`.
2. Runs `make ci` (staleness check + all tests, including the hidden one).
3. Prints JSON: `{"id", "passed": bool, "stale_generated": bool, "tests_run", "failures", "errors"}`.

A task **succeeds** only if `make ci` passes: the hidden test passes, no existing test breaks, and
generated models are fresh.

## Self-check

`demo/sandbox/selfcheck.py` verifies that every held-out and training item:
- fails its hidden test on the untouched sandbox, and
- passes after applying a reference solution (`demo/sandbox/solutions/<ID>.patch` or a Python
  function that edits the files), including `make gen` where required.

It also verifies the dead end (direct unittest fails with the guard message) and the obligation
(schema change without gen → `make ci` fails with the stale message).
